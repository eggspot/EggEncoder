Advanced Features

Waveform Generation

Every Probe call that decodes audio (WAV, AIFF, ALAC, FLAC, MP3, AAC, WMA, TTA, Opus, Vorbis, WavPack — not MOV/MP4, which is metadata-only unless a decodable audio track is found) populates ProbeResult.Waveform with a list of normalized peak values in [0, 1], one per window, via WaveformCalculator:

using EggEncoder.Waveform;

var calculator = new WaveformCalculator(totalSamplesPerChannel, channels, bitsPerSample);

int framesRead;
while ((framesRead = wavReader.ReadInterleavedSamples(buffer, 4096)) > 0)
{
    calculator.AddBlock(new ReadOnlySpan<int>(buffer, 0, framesRead * channels));
}

List<double> windows = calculator.GetNormalizedWindows(); // default 200 windows

WaveformCalculator streams — call AddBlock as many times as you like across however many decode callbacks the codec produces; it does not need the full signal in memory at once.

Sample-Accurate Cutting

NativeEncoder.CutFile (backed by AudioCutter.Cut) decodes any supported source (WAV, AIFF, ALAC, FLAC, MP3, AAC, WMA, TTA, Opus, Vorbis, WavPack, or MOV/MP4 with a mono AAC-LC audio track) and writes any supported destination format without re-encoding the untouched region where the format allows frame-boundary slicing:

using EggEncoder.Codecs;

bool produced = AudioCutter.Cut(sourcePath, destPath, startInSeconds: 30, endInSeconds: 90);
// false means the requested range was entirely outside the source's duration — no file was written

Source and destination extensions no longer need to match — Cut can transcode while it trims (e.g. cut a WAV directly to MP3). Use AudioCutter.Convert (or NativeEncoder.ConvertFile) when you just need format conversion with no trimming.

PCM Transform Pipeline

A PcmTransformPipeline runs a list of IPcmTransforms over every decoded block between decode and the destination write. It's opt-in — the plain Convert/Cut above are untouched and still fully streaming. See API Reference for the full type list; this section is a usage walkthrough. Resolve IPcmTransformEncoder from DI the same way as IMediaEncoder (both come from AddEggEncoder()), or use AudioCutter's static methods directly.

Resampling, gain, remix, bit depth, in one pipeline

using EggEncoder.Codecs;
using EggEncoder.Pcm;

var pipeline = new PcmTransformPipeline(
    new ResamplingTransform(sourceRate: 44100, targetRate: 48000, channels: 2),
    new ChannelRemixTransform(inputChannels: 2, outputChannels: 1),
    new VolumeTransform(gain: 1.5),
    new BitDepthFormatTransform(fromBits: 16, toBits: 24));

AudioCutter.Convert(sourcePath, destPath, pipeline);

Transforms run in the order given; each receives the previous one's output. A pipeline instance carries state across blocks (a resampler's source history, a peak normalizer's measured gain) and is meant for exactly one Convert/Cut/Mix call — build a fresh PcmTransformPipeline per call rather than reusing an instance.

Resampling quality, and why Flush() exists

ResamplingTransform is a Kaiser-windowed-sinc polyphase filter: it anti-aliases on downsample and band-limit-reconstructs on upsample, rather than a naive linear interpolation between neighboring samples. To do that correctly across an arbitrarily block-split stream, it holds a destination frame back until the source frames on both sides of it have actually arrived — including a few frames past the end of the current block. That means the very last few output frames of a stream can't be produced until the transform is told there's no more input coming:

int[] channels = ...;
var pipeline = new PcmTransformPipeline(new ResamplingTransform(sourceRate: 44100, targetRate: 48000, channels: 2));

// AudioCutter.Convert(pipeline)/Cut(options) already call Flush for you -- only a driver working
// against PcmTransformPipeline directly needs to do this itself:
var (buffer, frameCount, ch, sampleRate, bitsPerSample) = pipeline.Apply(sourceBlock, frameCount, 2, 44100, 16);
destSink.WriteInterleavedSamples(buffer, frameCount);
// ... more Apply() calls for subsequent blocks ...
var (tailBuffer, tailFrameCount, _, _, _) = pipeline.Flush(2, 44100, 16); // drains the resampler's pending tail
if (tailFrameCount > 0) destSink.WriteInterleavedSamples(tailBuffer, tailFrameCount);

IPcmTransform.Flush() is a default interface method (existing custom transforms don't need to implement it; the default is a no-op) that cascades through every transform in a pipeline in order — a resampler's flushed tail is pushed through every later transform's own Apply, exactly like one final block, before that transform's own Flush drains whatever it, in turn, is left holding. Total output frame count converges exactly on round(totalSourceFrames * ratio) once flushed, regardless of how the source was split into blocks.

Fades on a cut

AudioCutter.Cut(sourcePath, destPath, startInSeconds: 30, endInSeconds: 90, new CutOptions
{
    FadeInSeconds = 0.5,
    FadeOutSeconds = 1.0,
    FadeCurve = FadeCurve.EqualPower,
    Pipeline = new PcmTransformPipeline(new VolumeTransform(1.2)) // optional; runs after the fade
});

The fade runs over the retained range — 0..FadeInSeconds at the start, the last FadeOutSeconds at the end — before anything in Pipeline.

True whole-file peak normalization

Dropping PeakNormalizationTransform straight into a pipeline self-measures from whatever block Apply sees first — one ~4096-frame decode block, not the whole file. For a true whole-file measurement, measure first and hand the result in:

var (peak, bitsPerSample) = AudioCutter.MeasurePeakAmplitude(sourcePath);

var normalize = new PeakNormalizationTransform(targetDb: -1.0);
normalize.MeasurePeak(peak, bitsPerSample);

AudioCutter.Convert(sourcePath, destPath, new PcmTransformPipeline(normalize));

Mixing and concatenating

AudioCutter.Mix(
    [new MixInput(voicePath, Gain: 1.0), new MixInput(musicPath, Gain: 0.3)],
    destPath);

AudioCutter.Concatenate([introPath, bodyPath, outroPath], destPath);

Both require every input to share the same channels, sample rate, and bit depth — mismatches throw NotSupportedException. Mix decodes every input fully into memory (silence-pads the shorter ones to the longest), so it's meant for clip-length material, not multi-hour streams. Concatenate streams for every destination format except WAV; a WAV destination buffers the combined output in memory, since WavWriter needs an exact frame count at creation time and the combined total across sources isn't known until they've all been decoded.

Parametric EQ and FIR filtering

BiquadTransform is a single second-order IIR filter section using the RBJ Audio EQ Cookbook formulas — low/high pass, band pass, notch, all pass, peaking EQ, and low/high shelf:

using EggEncoder.Codecs;
using EggEncoder.Pcm;

// A gentle low-pass at 8kHz, then a notch to pull out 60Hz mains hum
var pipeline = new PcmTransformPipeline(
    new BiquadTransform(BiquadFilterType.LowPass, channels: 2, sampleRate: 44100, frequencyHz: 8000),
    new BiquadTransform(BiquadFilterType.Notch, channels: 2, sampleRate: 44100, frequencyHz: 60, q: 4.0));

AudioCutter.Convert(sourcePath, destPath, pipeline);

A single biquad section rolls off at 12 dB/octave. For a steeper, maximally-flat-passband low/high pass, ButterworthTransform cascades order / 2 BiquadTransform stages sharing one cutoff frequency, each at its own Q from the standard Butterworth pole-pair formula — filterType must be LowPass or HighPass (the other BiquadFilterType values have no standard higher-order cascade construction), and order must be a positive even integer:

// A steep, maximally-flat 4th-order low-pass -- twice the biquad's own rolloff
var steepLowPass = new ButterworthTransform(BiquadFilterType.LowPass, order: 4, channels: 2, sampleRate: 44100, frequencyHz: 8000);
var pipeline = new PcmTransformPipeline(steepLowPass);

For a filter shape neither of those covers, FirFilterTransform applies a caller-supplied tap array identically to every channel — general FIR convolution, matching ffmpeg's afir/general-FIR filters. It has no filter-design code of its own; accepting arbitrary taps (e.g. designed by an external tool) is the whole point:

double[] taps = ...; // from an external filter-design tool, or a hand-rolled window-based design
var pipeline = new PcmTransformPipeline(new FirFilterTransform(channels: 2, taps: taps));

All three keep per-channel filter history across blocks (two state values per channel per biquad stage; the last taps.Length - 1 samples per channel for FirFilterTransform) — build a fresh instance per Convert/Cut/Mix call, same as every other stateful transform, or call Reset() to restart that state without discarding the instance.

Float PCM

The pipeline itself is exclusively int[]-based — a normalized float sample (-1.0..1.0) maps 1:1 onto the 32-bit int native range every other bit depth already uses, the same scale WavReader produces when decoding a float WAV. For samples that don't go through a WAV file at all (synthesized audio, another library's float[] buffer):

using EggEncoder.Pcm;

int[] intSamples = FloatSampleConverter.FromFloat(myFloatSamples);
float[] backToFloat = FloatSampleConverter.ToFloat(intSamples, bitsPerSample: 32);

// Or directly against a WAV file:
AudioCutter.WriteWavFromFloat(destPath, myFloatSamples, channels: 2, sampleRate: 44100);
var (samples, channels, sampleRate) = AudioCutter.ReadWavAsFloat(sourcePath); // any WAV bit depth, normalized

WavWriter.Create(..., sampleFormat: WavSampleFormat.Float32) writes a real 32-bit IEEE float WAV. A float WAV source already decodes transparently into int PCM through Convert/Cut/Mix/Concatenate — no special handling needed. For a float destination through those same entry points, pass WavSampleFormat.Float32:

using EggEncoder.Codecs;

AudioCutter.Convert(sourcePath, destPath, WavSampleFormat.Float32);

AudioCutter.Cut(sourcePath, destPath, startInSeconds: 0, endInSeconds: 30, new CutOptions
{
    DestinationWavFormat = WavSampleFormat.Float32
});

AudioCutter.Mix(inputs, destPath, WavSampleFormat.Float32);
AudioCutter.Concatenate(sourcePaths, destPath, WavSampleFormat.Float32);

WavSampleFormat.Float32 requires the destination's bit depth to already be 32 (widen a narrower source first with a BitDepthFormatTransform in the pipeline — Mix/Concatenate have no bit-depth conversion of their own, so their sources must already be 32-bit) and throws NotSupportedException against a non-WAV destination. The default, WavSampleFormat.Integer, is unchanged from before this option existed. Internally, processing always stays int[]-based at the usual native-range scale — this only selects how WavWriter encodes that data on disk. float.NaN samples convert to silence (0), not the unspecified result of a raw (int)double.NaN cast; float.PositiveInfinity/NegativeInfinity clamp to +/-1.0, same as any other out-of-range value.

WavSampleFormat.MuLaw/ALaw select G.711 companded PCM the same way — they require the destination's bit depth to be 16 instead of 32. WavReader also decodes IMA ADPCM and MS ADPCM WAV files (decode only for both — two genuinely different algorithms, not variants of each other, despite the shared 4-bit coded width) automatically, with no API to opt in or out of either. See the README's format-coverage table for the full constraints on all three.

AIFF has the same float/G.711 destination-format story, via AiffSampleFormat instead of WavSampleFormat — Convert/Cut (via CutOptions.DestinationAiffFormat) take it the same way, and it's ignored for every destination that isn't .aiff/.aif/.aifc. Unlike WAV, AiffSampleFormat.Float32/Float64 are two separate values, not one — both decode/encode at the same int32-native-range scale (so both report/require bit depth 32), differing only in on-disk precision (4 vs 8 bytes per sample); LittleEndianInteger ('sowt') has no WAV equivalent at all, since WAV is already little-endian. Every non-Integer AiffSampleFormat value writes an AIFC container (FORM/AIFC) rather than plain AIFF — AiffReader reads AIFC automatically on the way in, the same no-opt-in-needed convention as WAV's own ADPCM decode.

AU (.au) follows the identical pattern once more, via AuSampleFormat/CutOptions.DestinationAuFormat — Float32/Float64 are the same two separate, same-scale values AIFC has, and MuLaw/ALaw work the same way too. The one difference from AIFF: AU has no LittleEndianInteger-equivalent value at all, since there's no AU convention for little-endian samples the way AIFC's 'sowt' exists for AIFF.

MOV/MP4 Probing and Audio Decode

MovProbe walks the ISO base media container's atom tree directly — no native dependency — to read duration, dimensions, and the video codec's four-character code. It's metadata-only and never decodes audio or video frames:

using EggEncoder.Codecs.Mov;

var result = MovProbe.Probe("clip.mp4");
Console.WriteLine($"{result.Width}x{result.Height}, {result.DurationInSeconds}s, {result.CodecFourCc}");

MovDecoder decodes an actual audio track when the file has one — a mono AAC-LC 'soun' track, specifically; it reads the MP4 sample table directly (no ADTS framing the way standalone .aac files have) and throws if the track is stereo or a different codec:

var streamInfo = MovDecoder.Decode("clip.mp4", (block, channels, sampleRate, bitsPerSample, totalSamples) =>
{
    // interleaved PCM samples for this chunk
});

NativeEncoder.Probe routes .mov/.mp4 files through both: ProbeResult.Width/Height/duration always come from MovProbe, and if MovDecoder successfully finds a decodable audio track, SampleRate/Channels/BitsPerSample/Waveform get populated too. If there's no audio track, or it's not mono AAC-LC, those fields stay null and the video metadata is still returned — audio decode failure never fails the whole probe. AudioCutter.Convert/Cut can also use a .mov/.mp4 file with a decodable audio track as a source, the same as any other format.

Native Binary Packaging

libmp3lame.dll, libFLAC.dll, and wavpackdll.dll are packed via the NuGet contentFiles convention so they land at Native/win-x64/*.dll relative to your application's output directory — exactly where NativeLibraryLoader's custom DllImportResolver looks for them at runtime, regardless of your app's working directory. No manual copy step is required after dotnet add package EggEncoder.

These binaries are Windows x64 only. EggEncoder does not run on Linux/macOS or non-x64 architectures — there is no cross-platform fallback engine.
