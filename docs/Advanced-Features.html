Advanced Features

Waveform Generation

Every Probe call that decodes audio (WAV, FLAC, MP3, AAC, WMA — not MOV/MP4) populates ProbeResult.Waveform with a list of normalized peak values in [0, 1], one per window, via WaveformCalculator:

using EggEncoder.Waveform;

var calculator = new WaveformCalculator(totalSamplesPerChannel, channels, bitsPerSample);

int framesRead;
while ((framesRead = wavReader.ReadInterleavedSamples(buffer, 4096)) > 0)
{
    calculator.AddBlock(new ReadOnlySpan<int>(buffer, 0, framesRead * channels));
}

List<double> windows = calculator.GetNormalizedWindows(); // default 200 windows

WaveformCalculator streams — call AddBlock as many times as you like across however many decode callbacks the codec produces; it does not need the full signal in memory at once.

Sample-Accurate Cutting

NativeEncoder.CutFile (backed by AudioCutter.Cut) decodes any supported source (WAV, FLAC, MP3, AAC, WMA) and writes any supported destination format (WAV, FLAC, MP3, AAC, WMA) without re-encoding the untouched region where the format allows frame-boundary slicing:

using EggEncoder.Codecs;

bool produced = AudioCutter.Cut(sourcePath, destPath, startInSeconds: 30, endInSeconds: 90);
// false means the requested range was entirely outside the source's duration — no file was written

Source and destination extensions no longer need to match — Cut can transcode while it trims (e.g. cut a WAV directly to MP3). Use AudioCutter.Convert (or NativeEncoder.ConvertFile) when you just need format conversion with no trimming.

PCM Transform Pipeline

A PcmTransformPipeline runs a list of IPcmTransforms over every decoded block between decode and the destination write. It's opt-in — the plain Convert/Cut above are untouched and still fully streaming. See API Reference for the full type list; this section is a usage walkthrough. Resolve IPcmTransformEncoder from DI the same way as IMediaEncoder (both come from AddEggEncoder()), or use AudioCutter's static methods directly.

Resampling, gain, remix, bit depth, in one pipeline

using EggEncoder.Codecs;
using EggEncoder.Pcm;

var pipeline = new PcmTransformPipeline(
    new ResamplingTransform(sourceRate: 44100, targetRate: 48000, channels: 2),
    new ChannelRemixTransform(inputChannels: 2, outputChannels: 1),
    new VolumeTransform(gain: 1.5),
    new BitDepthFormatTransform(fromBits: 16, toBits: 24));

AudioCutter.Convert(sourcePath, destPath, pipeline);

Transforms run in the order given; each receives the previous one's output. A pipeline instance carries state across blocks (a resampler's fractional position, a peak normalizer's measured gain) and is meant for exactly one Convert/Cut/Mix call — build a fresh PcmTransformPipeline per call rather than reusing an instance.

Fades on a cut

AudioCutter.Cut(sourcePath, destPath, startInSeconds: 30, endInSeconds: 90, new CutOptions
{
    FadeInSeconds = 0.5,
    FadeOutSeconds = 1.0,
    FadeCurve = FadeCurve.EqualPower,
    Pipeline = new PcmTransformPipeline(new VolumeTransform(1.2)) // optional; runs after the fade
});

The fade runs over the retained range — 0..FadeInSeconds at the start, the last FadeOutSeconds at the end — before anything in Pipeline.

True whole-file peak normalization

Dropping PeakNormalizationTransform straight into a pipeline self-measures from whatever block Apply sees first — one ~4096-frame decode block, not the whole file. For a true whole-file measurement, measure first and hand the result in:

var (peak, bitsPerSample) = AudioCutter.MeasurePeakAmplitude(sourcePath);

var normalize = new PeakNormalizationTransform(targetDb: -1.0);
normalize.MeasurePeak(peak, bitsPerSample);

AudioCutter.Convert(sourcePath, destPath, new PcmTransformPipeline(normalize));

Mixing and concatenating

AudioCutter.Mix(
    [new MixInput(voicePath, Gain: 1.0), new MixInput(musicPath, Gain: 0.3)],
    destPath);

AudioCutter.Concatenate([introPath, bodyPath, outroPath], destPath);

Both require every input to share the same channels, sample rate, and bit depth — mismatches throw NotSupportedException. Mix decodes every input fully into memory (silence-pads the shorter ones to the longest), so it's meant for clip-length material, not multi-hour streams. Concatenate streams for every destination format except WAV; a WAV destination buffers the combined output in memory, since WavWriter needs an exact frame count at creation time and the combined total across sources isn't known until they've all been decoded.

Float PCM

The pipeline itself is exclusively int[]-based — a normalized float sample (-1.0..1.0) maps 1:1 onto the 32-bit int native range every other bit depth already uses, the same scale WavReader produces when decoding a float WAV. For samples that don't go through a WAV file at all (synthesized audio, another library's float[] buffer):

using EggEncoder.Pcm;

int[] intSamples = FloatSampleConverter.FromFloat(myFloatSamples);
float[] backToFloat = FloatSampleConverter.ToFloat(intSamples, bitsPerSample: 32);

// Or directly against a WAV file:
AudioCutter.WriteWavFromFloat(destPath, myFloatSamples, channels: 2, sampleRate: 44100);
var (samples, channels, sampleRate) = AudioCutter.ReadWavAsFloat(sourcePath); // any WAV bit depth, normalized

WavWriter.Create(..., isFloatFormat: true) writes a real 32-bit IEEE float WAV (previously only readable, not writable). One limitation: AudioCutter.Convert/Cut/Mix/Concatenate don't preserve a WAV source's float-vs-integer format automatically — converting a float WAV through Convert today always produces an integer PCM WAV destination, because float-ness isn't threaded through the shared decode callback all 5 codecs use. Use ReadWavAsFloat/WriteWavFromFloat directly when you specifically need a float destination.

MOV/MP4 Probing and Audio Decode

MovProbe walks the ISO base media container's atom tree directly — no native dependency — to read duration, dimensions, and the video codec's four-character code. It's metadata-only and never decodes audio or video frames:

using EggEncoder.Codecs.Mov;

var result = MovProbe.Probe("clip.mp4");
Console.WriteLine($"{result.Width}x{result.Height}, {result.DurationInSeconds}s, {result.CodecFourCc}");

MovDecoder decodes an actual audio track when the file has one — a mono AAC-LC 'soun' track, specifically; it reads the MP4 sample table directly (no ADTS framing the way standalone .aac files have) and throws if the track is stereo or a different codec:

var streamInfo = MovDecoder.Decode("clip.mp4", (block, channels, sampleRate, bitsPerSample, totalSamples) =>
{
    // interleaved PCM samples for this chunk
});

NativeEncoder.Probe routes .mov/.mp4 files through both: ProbeResult.Width/Height/duration always come from MovProbe, and if MovDecoder successfully finds a decodable audio track, SampleRate/Channels/BitsPerSample/Waveform get populated too. If there's no audio track, or it's not mono AAC-LC, those fields stay null and the video metadata is still returned — audio decode failure never fails the whole probe. AudioCutter.Convert/Cut can also use a .mov/.mp4 file with a decodable audio track as a source, the same as any other format.

Native Binary Packaging

libmp3lame.dll and libFLAC.dll are packed via the NuGet contentFiles convention so they land at Native/win-x64/*.dll relative to your application's output directory — exactly where NativeLibraryLoader's custom DllImportResolver looks for them at runtime, regardless of your app's working directory. No manual copy step is required after dotnet add package EggEncoder.

These binaries are Windows x64 only. EggEncoder does not run on Linux/macOS or non-x64 architectures — there is no cross-platform fallback engine.
