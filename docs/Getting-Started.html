Getting Started

Install

dotnet add package EggEncoder

Targets net8.0, net9.0, and net10.0. The native codec binaries (libmp3lame.dll, libFLAC.dll) for win-x64 are bundled inside the package and copied to your output directory automatically — no separate install step.

Pick an Engine

EggEncoder exposes one interface, IMediaEncoder, with two implementations:

  • NativeEncoder — pure .NET codecs plus P/Invoke bindings to LAME and libFLAC. No external process. Use this unless you need a format the native codecs don't cover.
  • FfmpegEncoder — shells out to an ffmpeg/ffprobe binary you provide. Broader format support, including video container metadata.

Register with DI

using EggEncoder;

// Program.cs
builder.Services.AddEggEncoder(options =>
{
    options.UseNativeEncoder = true;
});

To use the ffmpeg engine instead:

builder.Services.AddEggEncoder(options =>
{
    options.UseNativeEncoder = false;
    options.FfmpegBinPath = @"C:\tools\ffmpeg"; // directory containing ffmpeg.exe and ffprobe.exe
});

FfmpegEncoderBinFactory validates both binaries exist at construction time and throws FileNotFoundException immediately if either is missing — EggEncoder does not download or provision ffmpeg itself.

Inject and Use

public class MediaService(IMediaEncoder mediaEncoder)
{
    public Task<ProbeResult> Inspect(string filePath) =>
        mediaEncoder.Probe(filePath);

    public Task Transcode(string sourcePath, string destPath) =>
        mediaEncoder.ConvertFile(sourcePath, destPath);

    public Task Trim(string sourcePath, string destPath, int startSeconds, int endSeconds) =>
        mediaEncoder.CutFile(sourcePath, destPath, startSeconds, endSeconds);
}

Without DI

Every type works standalone if you'd rather not use the DI extension:

using EggEncoder;
using Microsoft.Extensions.Logging.Abstractions;

IMediaEncoder encoder = new NativeEncoder(NullLogger<NativeEncoder>.Instance);
var probeResult = await encoder.Probe("track.flac");

Console.WriteLine($"{probeResult.SampleRate}Hz, {probeResult.DurationInSeconds}s");

Reading a ProbeResult

Probe returns the same ProbeResult shape regardless of which engine produced it:

public class ProbeResult
{
    public int DurationInSeconds { get; set; }
    public int? BitsPerSample { get; set; }
    public int? BitRate { get; set; }
    public int? SampleRate { get; set; }
    public int? Height { get; set; }   // set for video containers (MOV/MP4), null for audio
    public int? Width { get; set; }
    public string? Result { get; set; }          // raw JSON detail from the probing engine
    public string? WaveformResult { get; set; }   // JSON array of normalized peak windows, or null
}

See Advanced Features for waveform generation and sample-accurate cutting details, or the API Reference for the full type list.
