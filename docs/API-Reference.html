public enum AudioFormat { Wav, Aiff, Au, Flac, Mp3, Aac, Wma, Caf, Tta, Opus, Vorbis, WavPack, Mov }

The Stream-to-Stream overloads of ConvertFile/CutFile convert/cut between a source Stream and a destination Stream -- neither is disposed by the call. Backed by AudioCutter.Stream.cs's own Convert/Cut (see AudioCutter below), which reuse the exact same pipeline/fade/trim machinery the path-based overloads use. Source: every format Probe(Stream, AudioFormat) already supports. Destination: Wav/Aiff/Au/Flac/Tta/Aac/Wma so far, via WavWriter.Create(Stream, ...)/AiffWriter.Create(Stream, ...)/AuWriter.Create(Stream, ...)/FlacEncoder.OpenSession(Stream, ...)/TtaEncoderSession.OpenSession(Stream, ...)/AacEncoderSession.OpenSession(Stream, ...)/WmaEncoderSession.OpenSession(Stream, ...) -- every other destination codec's own Stream write side is still open, one format at a time. An unsupported AudioFormat on either side throws NotSupportedException. See feature-roadmap.md item 1 for status.

The Stream overload of Probe is for a source that isn't a local file (an HTTP response body, blob storage, an in-memory buffer) — it never disposes source. Implemented for every AudioFormat: AudioFormat.Wav/Aiff/Au/Caf/Vorbis/Mov (the stream must be seekable) and AudioFormat.Flac/Aac/WavPack/Tta/Opus/Wma/Mp3 (no seek requirement; read into memory up front); an undefined value throws NotSupportedException. Unlike the path-based Probe(string), AudioFormat.Mov has no file extension to distinguish a MOV container from an MP4 one, so it always reports FormatName/FormatLongName as "mov"/"QuickTime / MOV". See feature-roadmap.md item 1 for status.

The CancellationToken overloads of ConvertFile/CutFile check the token once per decoded block (real, sub-second cancellation for every format), via the single shared decode callback every codec's own decode loop already funnels through. Probe's own CancellationToken check is deliberately shallow instead — once, up front, before any decode starts — since Probe has no equivalent single shared callback across its own per-format methods. A cancelled call throws OperationCanceledException and produces no destination file. See feature-roadmap.md item 5.

Cut decodes any supported source (.wav, .aiff/.aif/.aifc, .au, .caf, .flac, .mp3, .aac, .wma, .tta, .opus, .ogg, .wv, or .mov/.mp4 with a mono AAC-LC audio track) and writes any supported destination extension — source and destination don't need to match, so it can transcode while it trims. PcmTransformPipeline & IPcmTransform — EggEncoder.Pcm

public interface IPcmTransform
{
    int OutputSampleRate { get; }      // 0 = passthrough
    int OutputChannels { get; }        // 0 = passthrough
    int OutputBitsPerSample { get; }   // 0 = passthrough
    bool CanChangeFrameCount { get; }
    (int[] buffer, int frameCount) Apply(int[] buffer, int frameCount, int channels, int sampleRate, int bitsPerSample);

    // Default interface method -- existing implementers don't need to change. Drains output this
    // transform is still holding back (e.g. a resampler's pending tail); call once, after the last
    // Apply() call for a stream. Most transforms hold no such state and keep the default (no output).
    (int[] buffer, int frameCount) Flush() => (Array.Empty<int>(), 0);
}

public sealed class PcmTransformPipeline
{
    public PcmTransformPipeline(params IPcmTransform[] transforms);
    public bool HasTransforms { get; }
    public IReadOnlyList<IPcmTransform> Transforms { get; }
    public bool CanChangeFrameCount { get; }
    public (int channels, int sampleRate, int bitsPerSample) ComputeOutputFormat(int inputChannels, int inputSampleRate, int inputBitsPerSample);
    public (int[] buffer, int frameCount, int channels, int sampleRate, int bitsPerSample) Apply(int[] inputBuffer, int frameCount, int channels, int sampleRate, int bitsPerSample);
    public (int[] buffer, int frameCount, int channels, int sampleRate, int bitsPerSample) Flush(int channels, int sampleRate, int bitsPerSample);
}

Apply is what AudioCutter.Convert/Cut call per decoded block; most consumers won't call it directly, but it's there if you're driving the pipeline yourself. Likewise Flush, which those same AudioCutter overloads call automatically once after the last block — see Advanced Features for why it exists and a worked example of calling it directly.

A pipeline instance carries cross-block state (a resampler's source history, a fade's frame position, a peak normalizer's measured gain) and is meant for exactly one Convert/Cut/Mix call — build a fresh one per call rather than reusing an instance across multiple calls.

public sealed class ButterworthTransform : IPcmTransform
{
    // filterType must be LowPass or HighPass (the other BiquadFilterType values have no standard
    // higher-order Butterworth cascade construction); order must be a positive even integer --
    // realized as order/2 cascaded BiquadTransform stages sharing the cutoff, each at its own Q
    // from the standard Butterworth pole-pair formula (maximally flat passband).

public sealed class FirFilterTransform : IPcmTransform
{
    public FirFilterTransform(int channels, double[] taps); // applied identically to every channel; no filter-design code of its own
    public void Reset(); // restart each channel's taps.Length - 1 sample history
}

Parametric EQ and FIR filtering: BiquadTransform is a single second-order IIR section using the RBJ Audio EQ Cookbook formulas (Direct Form II Transposed, two state values per channel) — low/high pass, band pass, notch, all pass, peaking EQ, and low/high shelf. ButterworthTransform cascades order / 2 BiquadTransform stages sharing one cutoff frequency, each at a different Q from the standard Butterworth pole-pair formula, for a steeper, maximally-flat-passband low/high pass than a single biquad section can provide. FirFilterTransform is general FIR convolution (parity with ffmpeg's afir/general-FIR filters) — it applies a caller-supplied tap array identically to every channel and keeps each channel's last taps.Length - 1 samples as history across blocks; accepting arbitrary taps is the whole point, so there's no filter-design helper bundled with it.

Peak normalization used naively: if PeakNormalizationTransform is dropped into a pipeline and never pre-measured, MeasurePeak self-measures from whatever buffer Apply first sees — which, driven by AudioCutter.Convert/Cut, is one ~4096-frame decode block, not the whole file. For a true whole-file measurement, call AudioCutter.MeasurePeakAmplitude first and pass its result to MeasurePeak(long, int) before handing the transform to a pipeline.

Loudness normalization has no such fallback at all: LoudnessTransform.Apply throws InvalidOperationException unless MeasureLoudness was already called — EBU R128's own gating algorithm cannot produce a meaningful number from one decode block the way a peak scan can, so there is no "measure from whatever block Apply sees first" shortcut to fall back to. Call AudioCutter.MeasureIntegratedLoudness first and pass its result to MeasureLoudness before handing the transform to a pipeline; a null or double.NegativeInfinity measurement both pass samples through unchanged.

Resampler quality: ResamplingTransform is a Kaiser-windowed-sinc polyphase filter — anti-aliasing on downsample, band-limited reconstruction on upsample — not linear interpolation. Output is held back until its full tap window (FilterHalfWidth source frames on each side) has genuinely arrived, rather than falling back to duplicating an edge sample at a block boundary; see Flush above for draining the last few frames this implies at the true end of a stream. Total output frame count is a cumulative floor(sourceFramesSoFar * ratio), so it's exact regardless of how a stream is split into blocks — no per-block rounding drift to account for. The continuous fractional source position is quantized to 1024 polyphase-table phases (a small, standard timing error for this class of resampler); downsampling scales the filter's half-width up by 1/cutoff to preserve anti-aliasing quality as the ratio shrinks, capped at 256 taps so an extreme ratio (e.g. 100:1) can't grow the table or per-sample cost unboundedly.

A fade, if requested, runs over the retained range before any transform in Pipeline. AudioCutter.Mix requires every input to share the same channels/sample rate/bit depth, and decodes all of them fully into memory, concurrently — clip-length material, not multi-hour streams. AudioCutter.Concatenate has the same format-matching requirement. WavSampleFormat selects a .wav destination's on-disk encoding (see Advanced Features for the float-WAV walkthrough); it's ignored for every other destination format. Float32 requires the destination's bit depth to already be 32; MuLaw/ALaw (G.711) require it to already be 16. AiffSampleFormat is the same idea for a .aiff/.aif/.aifc destination — LittleEndianInteger/Float32/Float64/MuLaw/ALaw all write an AIFC container regardless of which of those three extensions is used; Float32/Float64 require bit depth 32, MuLaw/ALaw require 16. AuSampleFormat is the same idea again for a .au destination — it has no LittleEndianInteger-equivalent value at all (AU is always big-endian), otherwise the same bit-depth requirements as AiffSampleFormat.

The Stream overload of Create doesn't dispose destStream, and — unlike every Stream-based reader in this project — needs no Stream.CanSeek at all: a WAV header's every size field is already known from totalFrames up front, so it writes the complete header once and never seeks back. It's the destination-Stream codec primitive IMediaEncoder.ConvertFile/CutFile's own Stream-to-Stream overloads use for a Wav destination (see IMediaEncoder above). See feature-roadmap.md item 1 for status.

Supports 8-bit unsigned, 16/24/32-bit signed integer, and 32-bit IEEE float PCM (both read and write — WavSampleFormat.Float32 requires bitsPerSample: 32). Also supports G.711 mu-law/A-law companded PCM, both read and write (WavSampleFormat.MuLaw/ALaw require bitsPerSample: 16; any channel count, unlike every other codec here), and three ADPCM variants (IsImaAdpcm/IsMsAdpcm/IsYamahaAdpcm, picked up automatically from the file's own fmt chunk on read, no opt-in needed). IMA ADPCM, MS ADPCM, and Yamaha ADPCM are genuinely different algorithms despite the shared 4-bit coded width — IMA ADPCM uses one universal fixed step table, MS ADPCM carries its own linear-prediction coefficient table in the fmt chunk extension itself and groups its block header by field across channels rather than repeating it per channel, and Yamaha ADPCM has no block structure at all (no per-block header, no wSamplesPerBlock extension — each channel's predictor/step state just carries continuously for the whole stream). All three are mono/stereo only. WavWriter also encodes all three (WavSampleFormat.ImaAdpcm/MsAdpcm/YamahaAdpcm, bitsPerSample: 16 required). IMA ADPCM and MS ADPCM are block-structured, unlike every other WavSampleFormat value: samples are buffered internally into fixed-size blocks (1024-byte block align, matching FFmpeg's own real encoder defaults) and only physically written once a block fills or WriteInterleavedSamples's caller calls Finish(), which also flushes and pads any final short block. Yamaha ADPCM instead writes two samples per byte continuously as they arrive, only ever holding back the one trailing nibble an odd mono frame count can leave pending, which Finish() flushes zero-padded. IMA ADPCM's own nibble is chosen by an 8-candidate search that always agrees with how this project's own decoder would reconstruct it, so encode and decode can never drift out of sync; MS ADPCM's and Yamaha ADPCM's own nibbles are each computed via their own direct closed-form formula instead (confirmed FFmpeg's real encoders' internal state-tracking formulas structurally match their own decoders', unlike IMA ADPCM's, so no search is needed), and MS ADPCM's encoder always selects the standard coefficient table's simplest pair for every block, matching FFmpeg's own real encoder exactly. All three are verified bit-exact against a real, independent ffmpeg decode of files they produced. Samples are always exchanged as int[], at this codebase's native-range convention for whatever bit depth is in play (see PCM Transform Pipeline); for float format that range is the full 32-bit int range, matching what a normalized -1.0..1.0 float sample maps to.

{
    if (!opened) { await writer.OpenAsync(source.Tracks!, cancellationToken); opened = true; }
    await writer.WriteAsync(packet, cancellationToken);
}
await writer.CompleteAsync(cancellationToken);

public sealed class FmpMediaSegmentWriter // stateful: one instance per rendition
{
    public FmpMediaSegmentWriter(MediaTrackSet tracks); // packet mode
    public FmpMediaSegmentWriter();                     // frame mode
    public byte[] BuildMediaSegment(IReadOnlyList<MediaPacket> packets, IReadOnlyDictionary<int, long>? nextDecodeTimes = null);
    public byte[] BuildMediaSegment(IReadOnlyList<Mp4EncodedFrame> frames);

Init segment. One trak per track, in the set's order; a track's MP4 track_ID is its position plus one (ffmpeg's default; packet track ids may be 0), and its mdhd timescale is its own Timescale, so timestamps are written exactly as given. The avcC/hvcC and AudioSpecificConfig bytes are copied as-is (avcC/hvcC are validated first). A video track with unknown dimensions gets them from its SPS; an AAC track with an unknown sample rate or channel count gets them from its AudioSpecificConfig. AAC may be mono or stereo. MP3, Opus, AV1 and VP9 tracks throw NotSupportedException; an empty set, a missing or invalid codec configuration, or a dimension or channel count past 16 bits throws ArgumentException. No edit list is written.

Media segments. One moof + mdat per call, with a traf for each track that has packets in it. Each tfdt is that track's first DTS in the segment, and each sample's duration is the next DTS of its track minus its own. The last sample of a track has no next DTS in the segment, so it takes, in order: the nextDecodeTimes entry for its track id (a segmenter that cuts when the next keyframe arrives knows the video one), the previous duration in the segment, the track's last duration from the previous segment, or a default of 1024 samples for AAC and 1/30 s for video. Because the next tfdt always comes from the real DTS, a guessed duration never accumulates drift. Video samples carry sync/non-sync flags and, when any PTS differs from its DTS, signed composition offsets (version 1 trun). Packets must belong to the set, carry their track's ConfigVersion, and have a non-negative DTS that strictly increases per track, across segments too; otherwise, or when an offset or duration doesn't fit 32 bits, the call throws ArgumentException and the writer is left unchanged. Timestamps are never rebased. Calling the other mode's BuildMediaSegment throws InvalidOperationException.

// Remux an FLV (or an RTMP ingest's packets) to fMP4: an init segment, then one segment per GOP.
await using var source = new FlvFileSource(File.OpenRead("in.flv"));
await using var output = File.Create("out.mp4");
FmpMediaSegmentWriter? writer = null;
var gop = new List<MediaPacket>();
await foreach (var packet in source.ReadPacketsAsync(cancellationToken))
{
    if (writer is null)
    {
        output.Write(FmpInitSegmentWriter.BuildInitSegment(source.Tracks!));
        writer = new FmpMediaSegmentWriter(source.Tracks!);
    }

    var isVideoKeyframe = packet.IsKeyframe && source.Tracks!.FindTrack(packet.TrackId)!.Kind == MediaKind.Video;
    if (isVideoKeyframe && gop.Count > 0)
    {
        output.Write(writer.BuildMediaSegment(gop, new Dictionary<int, long> { [packet.TrackId] = packet.Dts }));
        gop.Clear();
    }

    gop.Add(packet);
}

if (gop.Count > 0) output.Write(writer!.BuildMediaSegment(gop));

MPEG-TS from Packets

Namespace: EggEncoder.Streaming.MpegTs. Writes MPEG-TS segments (ISO/IEC 13818-1), the other segment format HLS serves, from packets: H.264 and H.265 video is passed through without decoding, next to AAC audio. This is item 5b of the live ingest & restream plan; the type also keeps its original single mono AAC track mode (new MpegTsMuxer(channels, sampleRate) and BuildSegment(IReadOnlyList<Mp4EncodedFrame>)), which the HLS segmenter uses today.

public sealed class MpegTsMuxer // stateful: one instance per rendition
{
    public MpegTsMuxer(MediaTrackSet tracks);          // packet mode
    public MpegTsMuxer(int channels, int sampleRate);  // frame mode
    public byte[] BuildSegment(IReadOnlyList<MediaPacket> packets);
    public byte[] BuildSegment(IReadOnlyList<Mp4EncodedFrame> frames);
}

Tracks. H.264 is written with stream_type 0x1B, H.265 with 0x24 and AAC as ADTS with 0x0F. A track's elementary PID is 0x100 plus its position in the set; video tracks get stream ids 0xE0 upward and audio tracks 0xC0 upward, so a set may hold at most 16 video and 32 audio tracks. The PCR rides on the first video track, or on the first track when there is no video. AAC must fit an ADTS header: audio object type 1-4 (so AAC-LC, or HE-AAC signalled implicitly, but not HE-AAC with explicit SBR/PS signalling, which fMP4 does accept), an indexed sample rate and a channel configuration of 1-7; anything else, and MP3, Opus, AV1 and VP9 tracks, throw NotSupportedException. An empty set or a missing or invalid codec configuration throws ArgumentException.

Segments. Each call returns one standalone .ts file: PAT, PMT, then one PES per packet, in DTS order (a stable sort, so packets may come grouped by track). Timestamps are rescaled to 90 kHz and written as given, modulo 233; nothing is rebased. A video PES holds the access unit in Annex B form: an access unit delimiter first (the packet's own, if it starts with one), then, on a keyframe that carries no SPS of its own, the parameter sets from the track's avcC/hvcC, then the packet's NAL units. Its PES_packet_length is 0 and it carries a DTS only when it differs from the PTS. An AAC PES holds one ADTS frame. Keyframe PES (and every AAC one) set random_access_indicator. The PCR is max(0, DTS - 700 ms), written on every PES of the PCR PID, with a PCR-only packet on that PID before another PID's PES when the segment has none yet or the last one is 100 ms old. The last TS packet of a PES is padded with adaptation-field stuffing. Continuity counters, PAT and PMT included, run on from one segment to the next, so a playlist of segments reads as one continuous stream. Packets must belong to the set, carry their track's ConfigVersion, have a PTS no earlier than a non-negative DTS that strictly increases per track (across segments too), a well-formed length-prefixed video payload, and AAC payloads of at most 8,184 bytes; otherwise the call throws ArgumentException and the muxer is left unchanged. Calling the other mode's BuildSegment throws InvalidOperationException.

// Remux an FLV (or an RTMP ingest's packets) to MPEG-TS segments, one per GOP.
await using var source = new FlvFileSource(File.OpenRead("in.flv"));
MpegTsMuxer? muxer = null;
var gop = new List<MediaPacket>();
var index = 0;
await foreach (var packet in source.ReadPacketsAsync(cancellationToken))
{
    muxer ??= new MpegTsMuxer(source.Tracks!);
    var isVideoKeyframe = packet.IsKeyframe && source.Tracks!.FindTrack(packet.TrackId)!.Kind == MediaKind.Video;
    if (isVideoKeyframe && gop.Count > 0)
    {
        File.WriteAllBytes($"segment{index++}.ts", muxer.BuildSegment(gop));
        gop.Clear();
    }

    gop.Add(packet);
}

if (gop.Count > 0) File.WriteAllBytes($"segment{index}.ts", muxer!.BuildSegment(gop));

Handshake. The simple handshake from the specification: version 3, then 1536-byte packets of time, zero and random bytes, each side echoing the other's. Versions 6 and 8 (RTMPE, Adobe's encrypted RTMP, out of scope) and every other version throw RtmpProtocolException. The echoes are not compared byte for byte, since digest-handshake publishers don't echo exactly; a real ffmpeg 9 publish completes against the simple handshake (checked in as a wire capture).

Chunk stream. The reader handles every message header type (0 absolute, 1 and 2 deltas, 3 repeating the previous delta, which right after a type 0 is that type 0's timestamp, as the specification describes), chunk stream ids 2 to 65,599 in one-, two- and three-byte basic headers, 32-bit extended timestamps (repeated on continuation chunks as the specification requires; a peer that leaves the repeat out, as some older publishers did, is recognised on its first continuation and read that way from then on), messages interleaved chunk by chunk across chunk streams, and zero-length messages. It applies Set Chunk Size, Abort and Window Acknowledgement Size itself before reporting them. Every bound is checked before anything is allocated, and buffers grow only as payload arrives, so a header that merely claims 8 MiB costs nothing. A chunk size, message length, chunk stream count or amount of partial data over its limit, a malformed control message, a type 1-3 header on a chunk stream that never had a type 0 one, and a new message header before the previous message on that chunk stream finished all throw RtmpProtocolException, after which the reader refuses further input. Because the reader waits for more bytes rather than guessing, truncation shows only when the caller says the input has ended: Complete() throws RtmpProtocolException if a chunk (header, extended timestamp or payload) or a message was cut short. The writer picks the most compact header the previous message on the chunk stream allows, switches to type 0 when the timestamp goes backwards, always repeats the extended timestamp, and never writes a type 3 directly after a type 0 (peers disagree on how to read that).

Commands. RtmpCommand.Decode wraps every AMF0 error (including its nesting, string and count bounds) in an RtmpProtocolException; a payload that stops after the name reads as transaction id 0 with a null command object. The factories build what publishers and servers exchange: connect (with app, type, flashVer, tcUrl and any extra properties such as Enhanced RTMP's fourCcList), the connect _result, createStream and its result, releaseStream/FCPublish/FCUnpublish, publish, play, deleteStream, _error and onStatus.

while (!handshake.IsComplete)
{
    var peer = new byte[handshake.BytesExpected];
    await network.ReadExactlyAsync(peer);
    await network.WriteAsync(handshake.Process(peer));
}

Security defaults. The server listens on 127.0.0.1 only until EndPoint says otherwise, and with no AuthorizePublishAsync every publish gets NetStream.Publish.BadName. Application names and stream keys are checked (non-empty, at most MaxNameLength characters, no control characters) before the callback sees them; a key already being published under the same application is refused until that publish ends (compared as an exact string, ?query included). Those checks make a name safe to compare, not to use as a path: /, \ and .. pass them, so never build a file name from one unmapped. Every chunk-level bound is ChunkReader's, the AMF0 bounds are Amf0Reader's, and each connection is timed out through every phase: the TLS and RTMP handshakes, getting to an accepted publish (the authorization callback's token is cancelled when that runs out, and a callback that ignores it is abandoned), a publisher that sends no media (pings don't count), and a consumer that leaves the packet queue full. A connection closes once its publish ends. A connection over MaxConnections is closed as soon as it is accepted, and a connection that breaks a bound is closed while every other connection carries on.

Packets and tracks. The server turns each RTMP audio, video and @setDataFrame/onMetaData message into packets with the same code FlvDemuxer uses for FLV tags, so the two give identical packets for the same tags (track ids 0 for video and 1 for audio, timescale 1000). It waits for the tracks the publisher's onMetaData names (videocodecid/audiocodecid), when that arrives before the first media message as it does from OBS and ffmpeg, and for both otherwise. Tracks changes, just before the first packet that uses it, when a track appears or a new sequence header changes its configuration (compare by reference to notice).

Backpressure and the end of a publish. Packets wait for the consumer in a bounded queue (PacketQueueCapacity, PacketQueueMaxBytes). When it is full the server stops reading from the publisher, which slows it down through TCP, and if the consumer stays away longer than ConsumerStallTimeout the publisher is disconnected; nothing is dropped. A publish ends when the publisher unpublishes or disconnects, on a timeout, when the server stops, or when the consumer calls Disconnect(): the enumeration then finishes normally after the last queued packet. Only a protocol violation or a malformed sequence header ends it with an RtmpProtocolException (an exception from a PublishStarted handler also ends it, faulted with that exception). Handlers run on the connection's task, so hand the stream off rather than blocking.

await using var server = new RtmpServer(new RtmpServerOptions
{
    EndPoint = new IPEndPoint(IPAddress.Any, 1935), // opt in to every interface
    AuthorizePublishAsync = (request, _) => ValueTask.FromResult(request.AppName == "live" && request.StreamKey == secretKey)
});
server.PublishStarted += (_, stream) => _ = Task.Run(async () =>
{
    await using var recording = new FlvWriter(File.Create("recording.flv"));
    MediaTrackSet? tracks = null;
    await foreach (var packet in stream.ReadPacketsAsync())
    {
        if (!ReferenceEquals(tracks, stream.Tracks))
        {
            if (tracks is null) await recording.OpenAsync(stream.Tracks!);
            else recording.UpdateTracks(stream.Tracks!); // a new sequence header mid-stream
            tracks = stream.Tracks;
        }

        await recording.WriteAsync(packet);
    }

    if (tracks is not null) await recording.CompleteAsync();
});
